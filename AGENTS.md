# Bubble — правила работы

- Bubble — социальная сеть на основе Commune (MIT). Сохранять лицензию и обязательные уведомления авторства.
- UI: Windows 7 / Frutiger Aero; использовать единые CSS-токены и общие компоненты.
- Перед изменениями проверять текущую ветку, статус Git и связанные файлы. Рабочая ветка UI — `wAs`; не предполагать, что копия чистая.
- Не перезаписывать чужие изменения. Перед изменениями API, БД, зависимостей и общих компонентов анализировать влияние; для выхода за согласованный объём получать разрешение.
- Без разрешения не переключать ветки и не выполнять merge, rebase, reset, clean, stash или force-push.
- Не создавать коммиты и PR без разрешения.
- Выполнять минимально необходимые проверки; сообщать, что фактически проверено и что осталось непроверенным.
- После отдельного этапа обновлять `docs/PROJECT_HANDOFF.md`, если изменились архитектура, реализованные функции или открытые задачи.
- Не записывать в документацию секреты, временные логи и неподтверждённые результаты.
- Контекст и границы ответственности: `docs/PROJECT_HANDOFF.md`. `apps/api/uploads/` не трогать в UI-задачах.
