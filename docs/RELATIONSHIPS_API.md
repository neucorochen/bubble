# Подписки и дружба: API

Все маршруты требуют Bearer access token. Запись требует активного аккаунта и, если включено требование, подтверждённой почты. Дружба существует при двух встречных подписках; отдельной записи дружбы нет.

- `POST /api/users/:username/follow` сохраняет прежний переключатель и не идемпотентен.
- `PUT /api/users/:username/follow` идемпотентно создаёт собственную подписку; уведомление отправляется только при создании.
- `DELETE /api/users/:username/follow` идемпотентно удаляет собственную подписку, не затрагивая обратную.

Все три метода возвращают профиль с существующим `followedByMe` и новым `followsMe`. Одновременные противоположные операции могут выполниться в любом порядке. После неопределённого сетевого результата клиенту следует обновить профиль; не повторять автоматически POST-переключатель.

`GET /api/users/me/relationships?type=friends|following|followers|outgoing|incoming&q=...&limit=20&cursor=...` возвращает `{ "items": [UserSummaryDTO], "nextCursor": string | null }`. `following` и `followers` по-прежнему включают друзей. `outgoing` и `incoming` включают только односторонние исходящие и входящие подписки. `type` обязателен, `q` необязателен (не более 50 символов, поиск по началу username без учёта регистра), `limit` от 1 до 50. Передавайте полученный курсор без изменений. Друзья сортируются по более позднему времени из двух подписок и ID исходящей записи по убыванию; остальные списки — по времени опорной подписки и её ID. Курсор списка друзей, полученный до изменения сортировки, следует сбросить. Ответ содержит только собственный список и исключает отсутствующие и заблокированные аккаунты. Состав может измениться между запросами страниц при изменении подписок или видимости.

При новом одностороннем `PUT` используется существующее уведомление `follow` с текстом о желании добавить в друзья. Повторный `PUT` и принятие входящей заявки нового уведомления не создают. Тип уведомления не менялся: существующие записи этого типа также отображаются с новым текстом. При одновременно созданных встречных подписках уведомление зависит от порядка серверных операций.

## Друзья профиля и приватность

`GET /api/users/me/relationships/counts` требует авторизацию и возвращает общие количества собственного аккаунта: `{ "friends": 7, "outgoing": 1, "incoming": 1 }`. Поиск и курсор на эти количества не влияют. Применяются те же фильтры доступности аккаунтов, что в списках. Одна агрегация с `$facet` рассчитывает все три категории; запрос кешируется клиентом и обновляется после изменения отношений.

Все маршруты профиля требуют авторизацию, включая `everyone`: анонимный просмотр профиля в существующей системе не предусмотрен. `PATCH /api/users/me/friends-visibility` принимает `{ "friendsVisibility": "everyone" | "friends" | "only_me" }` и меняет только настройку текущего активного пользователя. Для нового и существующего аккаунта без сохранённого поля используется `everyone`; миграции нет.

`GET /api/users/:username/friends/access` возвращает `{ "canView": false }` без счётчика при запрете; при разрешении — `{ "canView": true, "count": 0 }`. Только владельцу также возвращается его `friendsVisibility`. Счётчик исключает удалённые и административно заблокированные аккаунты и не зависит от поиска. `GET /api/users/:username/friends?q=...&cursor=...&limit=...` повторно проверяет права на каждый запрос и возвращает страницу как `GET /users/me/relationships`; при запрете — 403 без списка и счётчика. Заблокированный владелец скрывается от других на новых маршрутах друзей. Владелец всегда имеет доступ, `friends` допускает только взаимных друзей. Существующие маршруты подписок не меняют семантику.

Счётчик рассчитывается отдельной агрегацией при запросе доступа, а не в каждом ответе профиля или каждой странице; на больших объёмах необходимо измерить запросы с `explain` и оценить индексы сортировки. Уникальность зависит от фактически созданного в MongoDB уникального индекса `follower_1_following_1`, объявленного в модели. Его наличие и отсутствие старых дубликатов в целевой среде необходимо проверить отдельно; эта задача не создаёт миграцию.
