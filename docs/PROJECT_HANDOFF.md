# Bubble — передача контекста

## Backend взаимных подписок (локальная работа)

- Существующий Socket.IO доставляет сообщения и уведомления. При пересечении события с GET открытой переписки клиент отменяет устаревший запрос и сверяет диалог с API. MongoDB подтверждает переход в прочитанное условной записью. В открытых уведомлениях клиент учитывает каждое новое непрочитанное событие.
- Резервные интервалы при подключённом Socket.IO для переписки, списка диалогов и счётчика сообщений составляют 60/120/180 с, при отключённом — 15/45/30 с. Открытые уведомления, их счётчик и количества на собственной странице друзей проверяются раз в 30 с. Лента обновляется при открытии, возврате на вкладку и повторном выборе в навигации. Производительность запроса количеств на больших данных не измерена.
- После reload личные запросы и соединение ожидают подтверждения сеанса. Браузер повторяет временно неудачное восстановление сеанса и учитывает заголовок `Retry-After`. Старый признак гостя `0` перепроверяется один раз. Доставка сообщений, заявок и уведомлений, reconnect и загрузка ленты проверены в локальном Chrome с двумя аккаунтами, реальными API, Socket.IO и временной MongoDB. Конфигурация и задержки production не проверялись.

- Вкладки собственной страницы друзей показывают общие количества из `/users/me/relationships/counts`. Настройка приватности перенесена в четвёртую вкладку с шестерёнкой; на чужой странице элементы управления отсутствуют. Локальная сетка выравнивает высоту вкладок. Проверены 23 целевых backend-теста (включая временную MongoDB) и Chrome с имитацией API на 1440/390/320 px, ошибка сохранения и повтор.

- В профиле находится компактный блок последних шести друзей. Собственная страница `/friends` содержит друзей, односторонние исходящие и входящие заявки и настройку приватности; `/friends/:username` показывает только разрешённый список друзей. Сортировка друзей использует время возникновения взаимности; старый курсор такого списка нужно сбросить. Подписки и старый POST сохранены.
- Серверная приватность друзей: `everyone` / `friends` / `only_me`; для аккаунтов без настройки согласовано значение `everyone` без миграции. Владелец меняет настройку на странице друзей. Счётчик и список проверяют доступ на сервере; подписки и публикации сохранены. Детали: `docs/RELATIONSHIPS_API.md`.
- На ветке `friends_system` добавлены идемпотентные PUT/DELETE подписки, обратный флаг `followsMe` в профиле и авторизованный список собственных отношений с поиском и курсором. Прежний POST-переключатель сохранён. Контракты и ограничения: `docs/RELATIONSHIPS_API.md`.
- Дружба вычисляется по двум Follow-записям. Новый список скрывает административно заблокированных пользователей, как поиск. Уникальный индекс и конкурентность проверены на отдельной временной локальной тестовой MongoDB; наличие индекса и дубликатов в целевой БД не проверялось. Миграции и операции с production не выполнялись.
- Проверены 42 целевых backend-теста, включая интеграцию с временной MongoDB, typecheck и сборки API/web. Chrome с имитацией API: 1440 и 390 px, компактный блок, страница друзей, приватность, поиск, пагинация и четыре состояния отношений. Полный сценарий смены аккаунта, реальные авторизация и API в браузере, производительность на больших данных не проверены.

## Реализовано локально

- Общая светлая Aero-оболочка обычных маршрутов: стеклянная рамка, декоративные кнопки окна, синяя шапка, единый фон, панели и системные кнопки. Авторизация сохраняет отдельную компоновку с той же палитрой.
- Основное содержимое Aero-окна прокручивается нативно внутри `.shell`. Заголовок, баннер подтверждения и мобильная панель находятся вне этой области. Рамка фиксирована, а история сообщений сохраняет собственную прокрутку. Граница содержимого задаётся CSS-компоновкой окна без пересчёта обрезки в JavaScript.
- Единая конфигурация меню: Профиль, Лента, Поиск, Сообщения, Группы, События. Маршрут событий остаётся `/notifications`. Desktop, нижняя панель и бургер-меню используют одну конфигурацию; гостям доступны обзор, регистрация и вход.
- PNG-иконки навигации переиспользуются во всех вариантах меню. Общий компонент бренда использует новый логотип, сохранено название Bubble; favicon и существующие PWA-иконки обновлены.
- Декоративные акценты используют общий светло-зелёный токен `#bfec67`; цвета ошибок и опасных действий не заменялись.
- Основной интерфейс переведён на русский; относительное время использует `Intl.RelativeTimeFormat`, склонения — общую утилиту. Известные ошибки API переводятся на клиенте, неизвестные показываются нейтрально с HTTP-кодом; исходный текст хранится в объекте ошибки для диагностики. Исчерпывающая проверка всех состояний перевода не подтверждена.
- Лента открывается на подписках; все записи доступны второй вкладкой. Сохранены запросы, кеши и пагинация. В главном Composer скрыты платные поля и видимый счётчик, но лимиты и поддержка платных записей в остальных местах сохранены.
- Карточки ленты используют ширину под аватаром; удаление с подтверждением находится сверху справа. Время ведёт на отдельную страницу записи; аватары записей и комментариев ведут в профиль.
- Встроенные комментарии лениво монтируются при первом раскрытии, анимируются за 180 мс, сохраняют черновик. Закрытый блок получает `inert`; предусмотрен reduced motion.
- Встроенная и отдельная форма комментария используют однострочный input, кнопку «Отправить» и отключённую кнопку фото с подсказкой о будущей функции. API получает только текст.
- Desktop/mobile выход требует подтверждения через `window.confirm`; подписи нативных кнопок зависят от браузера.
- Общая правая колонка содержит заглушки сбора на сервер и дневника разработки; гостям показывается только дневник, ссылки «Обзор» / GitHub Bubble и динамический год. RSS убран из правой колонки, но маршрут News сохранён, как и Plus / Contact.
- Фон коротких страниц заполняет viewport; вкладки групп переиспользуют стили ленты. У сообщений форма и заголовок остаются видимыми, история прокручивается внутри диалога.

## Проверки и ограничения

Мобильная компоновка включается до 1100 px включительно, desktop — с 1101 px. Внутренний контур рисует .aero-fixed-frame::after; слой рамки имеет z-index: 32, поверх хедера (30). Размеры окна сохранены.

Firefox: box-shadow отключён внутри .aero-app, включая потомков и псевдоэлементы. Сохранены прежние ограничения blur и непрозрачный фон содержимого; границы, градиенты и цвета сохранены. Пользователь подтвердил исчезновение мерцания с диагностическим отключением box-shadow. Playwright Firefox работает вне песочницы; захват прокрутки не позволил достоверно подтвердить устранение кратковременного дефекта. Временный AeroDebug, query-параметр и все диагностические CSS-правила удалены.

Жалоба перенесена из нижних действий в общий PostCard: флажок справа сверху с title/aria-label «Пожаловаться», область 44×44 px. Используется прежняя ReportForm. Собственное удаление сохранено; административное удаление чужой записи остаётся в нижних действиях, без наложения на флажок. Общий компонент используется лентой, профилем, поиском, сообществами и страницей записи.

Финальная проверка: typecheck, CSS-парсинг и git diff --check прошли. Chrome и Playwright Firefox на 1440/390 px с имитацией API: свои/чужие карточки, открытие жалобы клавишей Enter, выбор причины, ошибка и повторная успешная отправка, форма на отдельной странице записи. Область флажка 44×44, горизонтального переполнения и диагностической панели нет (включая URL с прежним query-параметром). Проверка не заменяет реальный API; профиль/сообщества/поиск проверены по переиспользованию компонента, без полного прохождения сценариев.
