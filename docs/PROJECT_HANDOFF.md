## Реальный стек

По ранее изученным файлам текущей ветки: npm workspaces, TypeScript strict, React 18, Vite 6, React Router 6, TanStack Query 5, обычный CSS, Socket.IO client.
Монорепозиторий содержит `apps/web`, Express 4 / Mongoose API в `apps/api`, сервис `apps/realtime` и общие Zod-схемы/DTO в `packages/shared`.
README остаётся исходным описанием Commune: его бренд и ссылки не означают, что текущая UI-ветка совпадает с оригиналом.

## Реализовано локально

- Ссылки в постах, комментариях и сообщениях кликабельны; для первой ссылки в тексте показывается превью, а YouTube открывается во встроенном плеере. Метаданные обычных сайтов запрашиваются через авторизованный `/link-preview`: только HTTP(S), публичные IPv4-адреса с фиксацией адреса соединения и проверкой перенаправлений, лимиты времени и размера. Для недоступных сайтов остаётся карточка домена; IPv6-only сайты и изображения более 150 КБ не загружаются.

- Посты и личные сообщения поддерживают до 10 изображений и общий модальный просмотрщик. Изображения сообщений загружаются отдельно от публичных `/uploads`, доступ к ссылке проверяется по автору или участию в переписке; временные ссылки действуют 120 секунд. Закрытость S3-бакета и сквозная работа с реальным хранилищем ещё не проверены. Автоматическая очистка неиспользованных загрузок сообщений пока не реализована.

- В профиле выводятся три последних трека; «Открыть» ведёт в собственный раздел музыки либо в `/u/:username/music` с постраничной загрузкой видимой библиотеки. На странице `/music` по умолчанию открыта «Моя библиотека».

- Для новых загрузок музыки браузер считывает длительность из локального файла и передаёт её при подтверждении загрузки; если метаданные недоступны, загрузка продолжается без длительности. Ранее загруженные треки автоматически не обновляются. Значение поступает от клиента и не является проверенными сервером метаданными.
- В каталоге музыки добавлено скачивание через авторизованный API и временную ссылку хранилища с заголовком сохранения файла; работа с реальным хранилищем ещё не проверена.
- Плеер хранит источник текущей очереди: каталог, библиотека, профиль, публикация или сообщение. Подсветка и состояние кнопки соответствуют источнику, в том числе при паузе; переключение источника для текущего трека не перезапускает аудио.
- В плеере доступно управление принадлежностью текущего трека библиотеке; в полном режиме также доступно скачивание. Для актуального состояния используется авторизованный GET `/music/:id/library`.
- Общая строка музыки используется в каталоге, библиотеке, профиле, публикациях и сообщениях. Статусы принадлежности для списка запрашиваются пакетно через авторизованный POST `/music/library/status`; запрос ограничен 100 идентификаторами и возвращает только принадлежность текущему пользователю.

- Общая светлая Aero-оболочка обычных маршрутов: стеклянная рамка, декоративные кнопки окна, синяя шапка, единый фон, панели и системные кнопки. Авторизация сохраняет отдельную компоновку с той же палитрой.
- Прокручивается документ, полоса прокрутки у края viewport. Рамка фиксированная, верхние элементы sticky; нижняя горизонтальная рамка скрыта. В `App.tsx` обработчик прокрутки обновляет CSS-параметры обрезки содержимого, чтобы оно не проходило поверх стекла.
- Единая конфигурация меню: Профиль, Лента, Поиск, Сообщения, Группы, События. Маршрут событий остаётся `/notifications`. Desktop, нижняя панель и бургер-меню используют одну конфигурацию; гостям доступны обзор, регистрация и вход.
- PNG-иконки навигации переиспользуются во всех вариантах меню. Общий компонент бренда использует новый логотип, сохранено название Bubble; favicon и существующие PWA-иконки обновлены.
- Декоративные акценты используют общий светло-зелёный токен `#bfec67`; цвета ошибок и опасных действий не заменялись.
- Основной интерфейс переведён на русский; относительное время использует `Intl.RelativeTimeFormat`, склонения — общую утилиту. Известные ошибки API переводятся на клиенте, неизвестные показываются нейтрально с HTTP-кодом; исходный текст хранится в объекте ошибки для диагностики. Исчерпывающая проверка всех состояний перевода не подтверждена.
- Лента открывается на подписках; все записи доступны второй вкладкой. Сохранены запросы, кеши и пагинация. В главном Composer скрыты платные поля и видимый счётчик, но лимиты и поддержка платных записей в остальных местах сохранены.
- Карточки ленты используют ширину под аватаром; удаление с подтверждением находится сверху справа. Время ведёт на отдельную страницу записи; аватары записей и комментариев ведут в профиль.
- Встроенные комментарии лениво монтируются при первом раскрытии, анимируются за 180 мс, сохраняют черновик. Закрытый блок получает `inert`; предусмотрен reduced motion.
- Встроенная и отдельная форма комментария используют однострочный input, кнопку «Отправить» и отключённую кнопку фото с подсказкой о будущей функции. API получает только текст.
- Desktop/mobile выход требует подтверждения через `window.confirm`; подписи нативных кнопок зависят от браузера.
- Общая правая колонка содержит заглушки сбора на сервер и дневника разработки; гостям показывается только дневник, ссылки «Обзор» / GitHub Bubble и динамический год. RSS убран из правой колонки, но маршрут News сохранён, как и Plus / Contact.
- Фон коротких страниц заполняет viewport; вкладки групп переиспользуют стили ленты. У сообщений форма и заголовок остаются видимыми, история прокручивается внутри диалога.

## Музыка в feature/music-visuals

- На `/music` кнопка «Добавить музыку» открывает нативное модальное Aero-окно поверх оболочки и плеера. При ошибке поля сохраняются, при успехе окно закрывается, а запросы каталога и библиотеки инвалидируются. Цепочка sign → upload → complete сохранена.
- Название и исполнитель заполняются по имени файла и первому дефису. После выбора другого файла ручные правки сохраняются до сброса формы. Вкладки используют стиль ленты и поддерживают стрелки, Home и End.
- Глобальный плеер оформлен по нижней панели WMP 12: тёмная подложка, серебристый блок управления, синяя центральная кнопка и тонкий прогресс над управлением. До 1100 px он расположен над нижней навигацией с учётом safe area. Громкость восстанавливается в диапазоне 0–1.
- Добавлены компактный режим и кнопка восстановления, мобильный регулятор громкости скрыт. На desktop плеер шириной до 510 px всё ещё может перекрывать часть центральной колонки.
- Название трека и кнопки окна находятся в верхней рамке. В компактном режиме скрыт прогресс, на desktop доступна громкость. Длинное название прокручивается при переполнении с учётом reduced motion.
- Кнопка динамика выключает звук и повторным нажатием восстанавливает последнюю ненулевую громкость в текущем сеансе плеера.
- При ширине больше 1100 px плеер изначально расположен слева снизу и перемещается мышью за верхнюю рамку. При смене размера плеер сохраняет положение, ограничивая его границами окна. Позиции режимов сохраняются в браузере.
- Добавлены настройка видимости личной музыкальной библиотеки и постраничная карточка музыки в профиле. Сервер проверяет владельца и видимость до чтения библиотеки. Отсутствующая настройка означает «Все пользователи».
- Публикации и записи сообществ поддерживают до 10 музыкальных вложений из каталога или своей библиотеки. Метаданные платных вложений выдаются после проверки покупки. Выбор доступен через Composer, воспроизведение идёт через глобальный плеер. Личные сообщения ожидают отдельной реализации.

## Проверки и ограничения

Мобильная компоновка включается до 1100 px включительно, desktop — с 1101 px. Внутренний контур рисует .aero-fixed-frame::after; слой рамки имеет z-index: 32, поверх хедера (30). Размеры окна сохранены.

Firefox: box-shadow отключён внутри .aero-app, включая потомков и псевдоэлементы. Сохранены прежние ограничения blur и непрозрачный фон содержимого; границы, градиенты и цвета сохранены. Пользователь подтвердил исчезновение мерцания с диагностическим отключением box-shadow. Playwright Firefox работает вне песочницы; захват прокрутки не позволил достоверно подтвердить устранение кратковременного дефекта. Временный AeroDebug, query-параметр и все диагностические CSS-правила удалены.

Жалоба перенесена из нижних действий в общий PostCard: флажок справа сверху с title/aria-label «Пожаловаться», область 44×44 px. Используется прежняя ReportForm. Собственное удаление сохранено; административное удаление чужой записи остаётся в нижних действиях, без наложения на флажок. Общий компонент используется лентой, профилем, поиском, сообществами и страницей записи.

Финальная проверка: typecheck, CSS-парсинг и git diff --check прошли. Chrome и Playwright Firefox на 1440/390 px с имитацией API: свои/чужие карточки, открытие жалобы клавишей Enter, выбор причины, ошибка и повторная успешная отправка, форма на отдельной странице записи. Область флажка 44×44, горизонтального переполнения и диагностической панели нет (включая URL с прежним query-параметром). Проверка не заменяет реальный API; профиль/сообщества/поиск проверены по переиспользованию компонента, без полного прохождения сценариев.

Непроверенные или не полностью проверенные сценарии:

- Реальные API и авторизация (включая внешний вход и права доступа).
- Реальная загрузка изображений, платежи, отправка сообщений и Socket.IO.
- Экранная клавиатура и сенсорные сценарии на физических мобильных устройствах.
- Установка/обновление PWA и обновление иконок в кеше ОС.
- Все сочетания данных, ошибок, модальных окон и состояний перевода на всех страницах.
- Интеграция параллельных веток профиля, сообществ, музыки и инфраструктуры.
